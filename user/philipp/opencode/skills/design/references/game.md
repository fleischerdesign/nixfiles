# Game Design

## When to load & job

Load this when the artifact is a playable prototype and the question is how rules feel in play. Make the repeated decisions, consequences, and learning visible. Leave campaign-scale content, final assets, and production systems outside the prototype.

## Inputs

Bring the intended player experience, platform and controls, relevant game references, and any existing rules. Name the assumed player familiarity and session length if they're not specified. A small playable slice can explore the main mechanic without settling the whole progression.

## Decisions & process

Start with the decision the player repeats. If the pleasure is improvising, let a move solve one problem while creating another: spending a lantern charge reveals a shortcut but leaves less light for the return. If the pleasure is execution, use a reliable rule with room for mastery instead. You'll give up some surprise but make improvement easier to feel.

Choose which feedback loop should dominate. Let early gains compound when you want a run to feel increasingly powerful, knowing an early lead can make later choices less interesting. If you want tension through the last turn, make carrying more treasure cost movement or invite risk. That can preserve difficult choices, but the penalty may make success feel like punishment if the connection isn't clear in play.

Teach the mechanic in a situation where the player can try it and see the result. Use quick retries while they're learning the relationship between move and consequence. Introduce costlier losses later if commitment matters; longer resets add stakes but leave less time actually practicing the move.

## Typical mistakes & examples

Adding health to a puzzle enemy can turn a solved encounter into several identical turns. If difficulty should come from planning, change when the enemy moves or which tiles it blocks. Give that change a recognizable tell so players can revise a plan rather than guess at hidden rules.

## Deliverables & questions for the human

Share a playable loop with controls, a quick restart, and an early and later encounter. Show which rules are adjustable. Ask whether a lost attempt should invite experimentation or make choices feel weighty, and which strategies the game should reward.
