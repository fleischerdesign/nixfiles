# Knowledge card template

For authors, not runtime. Replace this title with one reusable method. Write 300–800 words in English. Teach the implementation step that entry modules can hand off, not a second overview of a discipline.

## Use when

Name the decision or artifact step that calls for the method, and the working artifact it produces.

## Inputs

Name the source materials, units, constraints, and owners that change the method. Distinguish supplied facts from assumptions and say what can still be derived when inputs are missing.

## Procedure

Show how to turn the inputs into the working artifact. Name the intermediate representation and the decision that leads to each step. Explain how the method changes under a likely constraint rather than prescribing a universal default.

## Limits

Distinguish what the artifact shows from what still requires site, participant, supplier, or specialist evidence. State the scope of standards and tool behavior; do not add checks, gates, scores, pass/fail, or approval claims.

## Worked example

Follow one specific input through the least obvious step to a visible outcome. Mark invented values as illustrative; do not use them as production or standard values.

## Sources

Name the relevant primary standard, original publication or textbook, or official documentation. Give the edition or tool version, section, and scope where applicable; mark uncertain details `verify` rather than guessing. Take production values from the project or supplier. Distinguish norms, project specifications, conventions, and example values. Do not assert exact normative thresholds from secondary accounts.
