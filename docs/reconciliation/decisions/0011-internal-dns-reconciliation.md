# 0011 - Internal DNS reconciliation

- **Status:** accepted
- **Date:** 2026-10-03

## Context

The fleet runs split-horizon DNS: one name answers differently on the public and internal planes. The
internal view is generated by Nix; a dynamic name needs it updated at run time. Updating only the
external record makes a name resolve publicly and fail internally - a silent, plane-specific outage
(**D2**, **S6**).

## Decision

A **single** reconciler owns both views of a dynamic name and applies them together. External and
internal records are derived from the same observed name set, so they cannot diverge per plane. The
resolution infrastructure itself remains Nix; only the dynamic records cross the line.

## Consequences

- A dynamic name is verified on both planes as one acceptance test (see [checks.md](../checks.md)).
- The reconciler needs write access to both the external provider and the internal resolver; that is a
  scoped credential, bridged like any other ([decisions/0010](0010-secrets-two-store-bridge.md)).
- Static names keep their present derivation; the reconciler adds dynamic records beside them.
- If the plane is down, declared names still resolve on both planes (**R8**); only new dynamic names
  wait.

## Alternatives

- **External only** - silently breaks the internal plane; rejected.
- **A second reconciler for the internal view** - two writers, two truths, and the split-horizon
  invariant becomes unprovable; rejected.
- **No dynamic internal names** - acceptable for some domains, but it must be a decision, not an
  accident.
