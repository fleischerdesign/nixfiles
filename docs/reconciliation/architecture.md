# Architecture

> The target architecture. Technology choices are recorded as ADRs under [`decisions/`](decisions/README.md);
> this document states how they compose. The invariants are defined in [model.md](model.md).

## 1. Three roles

```
        ┌───────────────────────────────────────────────────────────────┐
        │  Control plane   (Kubernetes Resource Model)                   │
        │                                                                │
        │     owned / declared ──┐            ┌── observed / imported     │
        │                        ▼            ▼                          │
        │              ┌────────────────────────────────┐                │
        │              │  reconcile:  providers · compositions             │
        │              │  domain logic = data                             │
        │              └───────────────┬────────────────┘                │
        └──────────────────────────────┼────────────────────────────────┘
                                       │ actuate
        ┌──────────────────────────────▼────────────────────────────────┐
        │  Actuators   pods · kata/microvm · systemd · external APIs     │
        └────────────────────────────────────────────────────────────────┘
             Nix:  substrate (NixOS) + pure compiler (seed, CRs, OCI)
```

- **Substrate - NixOS.** Immutable generations, the network, the firewall, the core services. Never
  reconciled by the control plane (invariant **R1**).
- **Control plane - the Kubernetes Resource Model.** Every run-time entity is an object with a spec, a
  status and an owner. One generic engine reconciles them.
- **Actuators.** The things that actually run: pods, sandboxes, systemd units, external APIs.

## 2. The chosen stack

| Role | Choice | ADR |
|---|---|---|
| Control-plane substrate | **k3s** (single server first), Traefik/service-LB/local-storage disabled | [0001](decisions/0001-substrate-k3s.md) |
| Desired-state delivery | **Flux** | [0002](decisions/0002-delivery-flux.md) |
| Reconciliation engine | **Crossplane** (compositions + providers) | [0003](decisions/0003-engine-crossplane.md) |
| Nix role | **substrate + compiler** (`nixidy`/`easykubenix`, OCI images) | [0004](decisions/0004-nix-as-compiler.md) |
| Identity policy vs entities | owned policy, observed users | [0005](decisions/0005-identity-ownership.md) |
| Scope | hybrid by pace | [0006](decisions/0006-scope-hybrid-by-pace.md) |

The stack is deliberately three roles, not three products that overlap: k3s is the API and the engine
runtime, Flux is delivery, Crossplane is the reconciliation engine with its extension points. Nothing
in the fleet names a backend; a service names a contract.

## 3. The resource model

Every reconciled entity exposes the same shape - the extension points are fixed, so no per-use-case
controller is written (**R7**).

| Field | Meaning | Source |
|---|---|---|
| `kind` | the entity class (`Gateway`, `Tenant`, `Membership`, ...) | a CRD (XRD) |
| `spec` | desired state | Git, compiled by Nix or authored as a CR |
| `status` | observed state | written by the engine, never by a human |
| `ownerReferences` | lifecycle linkage for cascade/orphan | the engine |
| `labels` | ownership and scope (`vyrx.dev/owner=declared\|observed\|derived`) | the writer |

Domain logic lives in exactly two reusable artifacts:

- **Providers** - translate an external API to objects (Authentik, Cloudflare, SQL, ...). Generic and
  API-shaped; reused across domains.
- **Compositions** - map one object to many (a `Gateway` to a Deployment, Service, Ingress, Secret and
  backup object). Declarative; no code unless a composition function is genuinely needed.

## 4. Nix's role

Nix keeps three jobs and loses one:

- **Keeps:** substrate (NixOS), packaging and OCI images, and *pure* compilation of desired state -
  platform CRs and policy generated at evaluation time, consumed by Flux.
- **Loses:** being the system of record for run-time entities. That moves to the control plane.

Desired state generated by Nix uses the rendered-manifest pattern: Nix emits manifests, Flux applies
them continuously. Nix remains the single language for everything static; it does not learn a second
configuration language, and it does not read live state (**R2**).

## 5. Bootstrap and ownership

The control plane cannot manage itself (**R1**). The sequence is fixed:

1. **Seed (Nix):** NixOS installs and starts k3s with a known server token and the Flux entry point.
2. **Adopt (Flux):** Flux reconciles the platform CRs from the Nix-rendered manifests and takes over.
3. **Operate:** everything above L3 is reconciled; L0-L3 stays Nix.

Ownership is enforced by label and by admission, not by convention: a `declared` object is not edited
by a provider, an `observed` object is not edited by Git. Conflicts are rejected, not silently resolved
(**R3**, **R4**).

## 6. Security model

Adopting a control plane promotes a new asset - the API - to the highest-value target in the fleet.

- **Reachability:** the API server listens on the WireGuard address only, never publicly; ingress to it
  is a `publication` with `auth` and a `directAccess` scope like any other service. This reuses the
  existing exposure and firewall projections rather than inventing a second model.
- **Authentication:** OIDC through Authentik, with a **break-glass** local admin that does not depend on
  Authentik, because the control plane must be recoverable while the identity provider is down.
- **Authorisation:** RBAC per namespace; a workload cannot read another tenant's secrets.
- **Admission:** quotas and rate limits, so a runaway controller cannot provision unbounded entities.
- **Supply chain:** controller and provider images are pinned by digest by Nix, which is a standing
  advantage of keeping Nix as the compiler.
- **Secrets:** platform secrets stay in SOPS; entity secrets live in the control plane's store, bridged
  explicitly - see [ownership.md](ownership.md) §4.

## 7. Failure and degraded mode

Failure is bounded by design (**R8**):

- The control plane is unavailable -> dynamic entities are not reconciled; static services (DNS, DHCP,
  ingress, mail, media) keep running because they are NixOS units that never query it.
- A host reboots without the control plane -> it boots and serves; only its dynamic workloads wait.
- Loss of the control plane's own state -> rebuilt from the Nix seed plus the entity-state backup
  (see [edge-cases.md](edge-cases.md), risk E7).

The control plane is therefore **not** in the critical path of the fleet's basic function. This is the
property that keeps the change reversible.
